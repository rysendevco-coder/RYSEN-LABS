# Pokemon Sniper Project Context Example

This is an example project-context document only. It does not create or refactor Pokemon Sniper code.

## Project Summary

Pokemon Sniper is described at a high level as an existing Python application. Before architecture decisions become final, the existing codebase should be inspected.

## Current Assumptions

- The application may contain useful domain logic that should be preserved.
- The current structure may need clearer application and service boundaries.
- Testing strategy should be based on observed behavior.

## Possible Future Direction

- A clean application/service boundary.
- A backend API where appropriate.
- A Flutter client.
- Shared domain models.
- Automated tests.
- Reproducible release workflows.

## Provisional Architecture Notes

All architecture notes are provisional until the existing codebase is inspected. No backend framework, database, Flutter architecture, or release process should be selected without project-specific evidence.

Use the Orchestrator to inspect project context and create a discovery plan. Use the Reviewer in read-only mode to identify risks before implementation begins.
