# Coding Standard

Version 0.1.0 does not prescribe a language-specific coding standard. Projects should define local standards after selecting their stack.

## Universal Standards

- Keep changes small and cohesive.
- Name concepts consistently.
- Separate domain logic from delivery mechanisms where practical.
- Document public contracts and breaking changes.
- Avoid hidden global state.
- Validate inputs at boundaries.
- Keep secrets out of source control.
- Add or update tests for behavior changes.

## Project-Specific Standards

When a project adopts this framework, it should extend this document or add local standards for its selected language, framework, formatter, linting rules, and test strategy.
